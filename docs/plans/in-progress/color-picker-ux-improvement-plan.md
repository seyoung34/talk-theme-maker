# 컬러 피커 UX/UI 개선안

> 상태: Phase 1 및 Phase 2 구현 완료. 반응형·접근성 검증과 실기기 검증이 남아 있다.
> 참고: 문서 인덱스 → [../../README.md](../../README.md)

## 목적

테마 편집 중 색을 고르는 행동을 빠르고 예측 가능하게 만든다. 사용자는 “색을 골라 즉시 미리보기에서 확인”할 수 있어야 하며, 색상 코드·투명도 같은 정밀 조정은 필요할 때만 사용해야 한다.

## 근거와 문제

제공된 Android 스크린샷과 현행 구현을 기준으로 다음 문제가 확인됐다.

1. 브라우저 기본 `input[type="color"]`는 Android와 iOS마다 완전히 다른 UI가 열려 제품 경험을 통제할 수 없다.
2. 처음 도입한 커스텀 시트는 제목, 현재 RGB, 고정 팔레트, 완료 버튼이 선택 행동보다 더 큰 비중을 차지했다.
3. 모바일과 데스크톱이 각각 `MobileQuickEditPanel`, `ProjectQuickEditPanel`에서 별도 구현되어 동작과 레이아웃이 어긋날 위험이 있다.
4. 넓은 화면의 모바일 레이아웃에서 모달 폭이 색상 평면보다 커져 의미 없는 가로 여백이 발생했다.
5. 색 선택값은 즉시 프로젝트 상태에 반영되지만, 닫기/취소의 의미가 명확하지 않다.

## 확정 UX 방향

### 노출 방식

| 환경 | 노출 | 이유 |
|---|---|---|
| 모바일(1024px 미만) | 화면 중앙의 컴팩트 모달 | 편집 시트와 미리보기 위에서 터치 실수를 막고, 색상 평면을 충분히 크게 유지한다. |
| 데스크톱 | 색상 스와치에 앵커된 Popover | 미리보기를 가리지 않고 현재 편집 맥락을 유지한다. |
| 공통 진입점 | 색상 필드의 44px 이상 스와치 버튼 | 사용자는 별도 “색상 선택” 메뉴를 찾지 않고, 현재 색을 눌러 바로 연다. |

### 피커 안에 남길 것

- 채도·명도 2D 평면
- Hue 슬라이더
- 현재 선택 위치를 보여 주는 포인터
- 키보드와 터치 조작

### 피커 밖에 둘 것

- HEX / Android `#AARRGGBB` 입력: 피커 옆 또는 바로 아래의 정밀 입력 필드
- 투명도 슬라이더: 색상 필드 아래의 독립 컨트롤
- 추천 색상: 고정 무지개 팔레트가 아니라 자동 맞춤이 가능한 슬롯에서만 기존 “추천 색상 적용” 버튼으로 노출
- 색상 맥락 미리보기와 대비 경고: 편집 패널의 후속 정보로 유지

즉, 피커 자체는 색을 고르는 도구만 보여 주고, 설명·코드·프리셋·완료 버튼은 피커 내부에 넣지 않는다.

## 상호작용 규칙

1. 스와치를 누르면 현재 RGB와 알파를 기준으로 피커가 열린다.
2. 평면 또는 Hue 슬라이더를 드래그하는 동안 미리보기와 HEX 입력은 즉시 갱신한다.
3. 모달 밖을 탭하거나 Esc를 누르면 닫되, 마지막 색상은 유지한다. 현행 즉시 반영 모델과 일관성을 유지한다.
4. 실수 복구는 색상 코드 필드의 이전값 재입력 또는 향후 편집 Undo 기능으로 해결한다. 이 계획 범위에는 별도 취소/적용 버튼을 넣지 않는다.
5. 모달의 폭은 `min(440px, 100vw - 32px)`로 고정하고, 색상 평면은 모달의 가용 폭을 모두 쓴다. 가로 빈 공간을 만들지 않는다.
6. iPhone 안전 영역과 Android 제스처 영역을 고려해 모달이 화면 밖으로 나가지 않게 한다.

## 정보 구조

```text
색상 슬롯 카드
├─ 현재 색상 스와치 버튼  →  컬러 피커(2D 평면 + Hue)
├─ HEX / #AARRGGBB 입력
├─ 투명도 슬라이더
├─ 자동 맞춤 추천(해당 슬롯만)
└─ 대비 경고·맥락 미리보기(해당 슬롯만)
```

## 구현 계획

### Phase 1 — 공용 컴포넌트 추출

- [x] `components/project/ThemeColorPicker.tsx`를 만든다.
- [x] `react-colorful`의 `HexColorPicker`와 공통 다이얼로그/팝오버 래퍼를 한 곳에서 관리한다.
- [x] 모바일·데스크톱 패널에서 네이티브 `input[type="color"]`와 중복 다이얼로그를 제거한다.
- 완료 기준: 두 편집 패널이 같은 RGB 보존·알파 보존 로직과 같은 피커 컴포넌트를 사용한다.

### Phase 2 — 반응형 노출과 접근성

- [x] 모바일 중앙 모달과 데스크톱 앵커 Popover를 구현한다.
- [ ] 모달 폭, 안전 영역, 포커스 트랩, Esc/바깥 클릭 닫기를 검증한다.
- [x] 스와치 버튼의 접근 가능한 이름과 피커의 숨은 제목/설명을 유지한다.
- 완료 기준: 320px 폭부터 대형 데스크톱까지 가로 여백·잘림 없이 조작 가능하다.

### Phase 3 — 실기기 검증

- [ ] Android Chrome 및 Samsung Internet에서 터치 드래그, 스크롤 잠금, 모달 닫기를 확인한다.
- [ ] iOS Safari에서 터치 드래그, 뷰포트 높이, 안전 영역, 키보드 노출을 확인한다.
- [ ] RGB 변경 뒤 Android 알파값이 유지되는지 확인한다.
- 완료 기준: 두 플랫폼에서 브라우저 기본 색상 선택기가 열리지 않고, 색상 변경이 미리보기·내보내기에 동일하게 반영된다.
